# ADR: 元データの保存先を Google Sheets に統一する

- Status: Accepted
- Date: 2026-03-18T13:37:08+09:00
- Supersedes: なし

## Context

共通入口では、`Playwright` で取得した候補を既存の元データと照合し、`uniqueId` ベースで重複判定する必要がある。

この元データの保存先が未確定だと、重複チェックの実装と運用フローが固まらない。

運用上は非エンジニアでも扱いやすく、後段の確認結果も追記しやすい保存先が望ましい。

## Decision

- 元データの保存先は `Google Sheets` に統一する
- 共通入口では、`Google Sheets` に保存済みの `uniqueId` を読み取り、重複判定に使う
- 重複でない候補は、同じ `Google Sheets` に追記して元データを更新する
- 後段の `Gemini API` 判定結果や `Backstage` 確認結果も、同じ候補行に追記できる前提で列設計する

## Consequences

- 重複判定の基準データが 1 か所に集約される
- 非エンジニアでも候補一覧を直接確認しやすい
- `n8n` 連携と相性がよい
- 行単位の更新設計を先に決めないと、後段の結果追記が煩雑になりやすい
